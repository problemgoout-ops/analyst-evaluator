## 🔴 ПРИОРИТЕТ 1 — КРИТИЧЕСКИЕ GAP (разрыв = 2)

### 1. Методологии анализа процессов
- **Сейчас:** ❌ Не знаю
- **Надо:** 🛠 Применять на практике
- **Чему учиться:** SWOT-анализ, причинно-следственный анализ (диаграмма Исикавы), анализ разрывов (gap-анализ), PEST-анализ
- **Как:**
  - Пройти мини-курс по методологиям анализа (YouTube + статьи)
  - На каждом проекте применять минимум 1 метод: описать проблему → выбрать метод → провести анализ → зафиксировать вывод
  - Завести привычку: перед описанием процесса задавать себе вопрос «каким методом анализирую?»
- **Срок:** 4 недели

### 2. Принципы и методы оптимизации
- **Сейчас:** ❌ Не знаю
- **Надо:** 🛠 Применять на практике
- **Чему учиться:** Lean (устранение потерь), Six Sigma (снижение вариативности), вертикальное/горизонтальное сжатие процессов, устранение узких мест
- **Как:**
  - Изучить 8 видов потерь Lean (DOWNTIME) — заучить наизусть
  - На каждом описанном процессе находить минимум 1 потерю и формулировать предложение по оптимизации
  - Практика: взять реальный процесс из текущего проекта, применить Lean-линзы, описать «было → стало»
- **Срок:** 4 недели

### 3. Исследование и сбор информации
- **Сейчас:** 📖 Знаю теорию
- **Надо:** 🦾 Профи-уровень
- **Чему учиться:** интервьюирование стейкхолдеров, подготовка вопросов, техника активного слушания, фиксация результатов интервью
- **Как:**
  - Провести минимум 5 интервью с бизнес-заказчиками (под руководством мидла+)
  - Перед каждым интервью готовить список вопросов, после — сразу фиксировать ответы
  - Запросить обратную связь от интервьюируемых: «понятно ли вёл беседу, все ли темы покрыл?»
  - Развить навык: не просто спрашивать, а понимать скрытые потребности
- **Срок:** 6 недель

### 4. Типизация требований
- **Сейчас:** 📖 Знаю теорию
- **Надо:** 🦾 Профи-уровень
- **Чему учиться:** функциональные / нефункциональные требования, бизнес-требования / пользовательские истории / системные требования, атрибуты требований (приоритет, источник, статус)
- **Как:**
  - На каждом проекте классифицировать ВСЕ собранные требования по типам
  - Создать шаблон: «Требование → Тип → Приоритет → Источник → Статус»
  - Практика: перепроверить последние 3 своих документа с требованиями — все ли типы покрыты
- **Срок:** 4 недели

## 🟡 ПРИОРИТЕТ 2 — ПЕРЕХОД ОТ «ЗНАЮ» К «ПРИМЕНЯЮ» (GAP = 1)

### Блок: Анализ бизнес-процессов

| Навык | Что делать конкретно |
|-------|---------------------|
| BABOK | Взять любой реальный процесс и провести по нему BABOK-анализ: входы, выходы, стейкхолдеры, задачи |
| Нотации (BPMN/EPC) | Нарисовать 3 процесса в BPMN (начать с простого — согласование документа, затем сложнее). Инструмент: Camunda Modeler (бесплатный) |
| Бизнес-контекст | Перед каждым проектом писать 1 абзац: «как этот процесс влияет на бизнес-цели компании» |
| Описание процессов (схемы) | Создать 3 BPMN-схемы реальных процессов из текущих проектов |
| Описание процессов (текст) | Написать 2 бизнес-процедуры / регламента по реальным процессам |
| Выявление проблем | На каждом описанном процессе отмечать: узкие места, дублирование, риски ошибок |
| Аналитическое мышление | Практика «5 почему»: к каждой проблеме задавать 5 уровней вопроса «почему?» |

### Блок: Документирование

| Навык | Что делать конкретно |
|-------|---------------------|
| Инструменты (Confluence) | Все рабочие документы вести ТОЛЬКО в Confluence. Создать структуру пространства для проекта |
| Структурирование информации | Перед написанием документа — набросать структуру (заголовки 2 уровня). Проверять: нет ли избыточности |
| Работа с документами | Шаблонизировать: создать 3 шаблона (ТЗ, регламент, отчёт по анализу) |
| JIRA / аналоги | Все задачи вести в JIRA. Создавать эпики → стори → таски для каждого проекта |

### Блок: Методологии

| Навык | Что делать конкретно |
|-------|---------------------|
| Scrum / Kanban / Lean | Выбрать один текущий проект и провести его по спринтам. Вести доску. Проводить дейли |

### Блок: Коммуникации

| Навык | Что делать конкретно |
|-------|---------------------|
| Эмоциональный интеллект | Практика: на встречах фиксировать «что хотел сказать заказчик» vs «что сказал вслух». Развивать чтение между строк |

### Блок: Реинжиниринг

| Навык | Что делать конкретно |
|-------|---------------------|
| Методы оптимизации (Lean, Six Sigma) | Изучить теорию: диаграмма Парето, метод 5S, DMAIC. Применить Парето к одному реальному процессу |

## 📋 РЕЖИМ РАЗВИТИЯ

### Еженедельно:
- [ ] 1 BPMN-схема реального процесса
- [ ] 1 интервью с бизнесом (с фиксацией)
- [ ] 1 анализ проблемы методом «5 почему» или Исикавы
- [ ] Все документы в Confluence

### Ежемесячно:
- [ ] 1 регламент / бизнес-процедура
- [ ] 1 применение Lean-линз к реальному процессу
- [ ] Ревью с мидлом+: что выросло, где застрял

### Критерий перехода на Мидл:
- Все критические GAP закрыты (4 компетенции)
- Минимум 80% GAP=1 закрыты (14 из 18)
- Самооценка подтверждена руководителем
